## Proposed envelope — not authorization to switch mode

One activation, stopped at the **first** trigger below; no extension, reset or second epoch under this approval:

| Limit | Proposed trigger | Previous trigger |
|---|---:|---:|
| Time since STAGING mode request (includes startup) | 12 minutes | 10 minutes |
| Observed PostgreSQL TCP payload RX on the machine | 20,000,000 bytes | 15,000,000 bytes |
| Observed whole-machine RX | 26,000,000 bytes | 20,000,000 bytes |
| Guest available memory | below 192 MiB | below 192 MiB |
| Database physical size (`pg_database_size`, sampled SELECT-only) | at or above 400,000,000 bytes | preflight only |

The traffic limits are **observed stop triggers, not hard caps or billed Supabase egress**. One-second DB socket samples and approximately two-second controller checks, machine replacement and shutdown can overshoot; sockets created and closed between samples can be missed. Whole-machine RX includes FPL and diagnostic traffic. Keep sampling through OFF as far as possible and disclose the missing tail. Do not raise a threshold to obtain a success signal. The physical DB-size guard leaves nominal room below the Free 0.5 GB allowance but does not substitute for the provider dashboard; stop if that dashboard shows insufficient storage even when the SQL size is lower.

Health is public app health, not `/ops/sync/health` (which may be DOWN before verification). The memory and storage stops require trustworthy samples; missing samples stop, not fail open.

Also stop on an observed or staged HTTP 429, a persisted `SETTLEMENT_UNCERTAIN`/`HTTP_EXCHANGE_UNCERTAIN` run, or a request attempt remaining unfinished for three minutes after admission. Preserve all unresolved attempt evidence for manual reconciliation. An ordinary in-flight row alone is **not** a stop trigger. Do not assume an unknown HTTP result had no Retry-After header.
