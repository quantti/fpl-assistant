# Free Tier Implementation Plan

**Spec:** `docs/superpowers/specs/2026-08-22-free-tier-design.md` — read it first; this plan
argues from it and does not repeat its reasoning.

**Goal:** A permanent free tier of 20 messages per rolling seven days, reached through a
self-serve sign-up gated by an invite code with a hard account cap, enforced on the server.

**Architecture:** Phase 5a already ships the metering: an append-only `fpl_usage_event`, a
rolling seven-day count under a per-user advisory lock, and a per-user override column. This
phase configures that apparatus (default 20), adds a derived `Plan` seam so free and paid can
tell the user different things, and adds one endpoint — `POST /api/auth/signup` — that checks an
invite code, reserves a slot in a new `fpl_invite_redemption` ledger, and creates the account
through Supabase's Admin API with the service-role key.

**Tech stack:** Spring Boot 4.1 / Java 25, `JdbcTemplate`, `RestClient`, MockMvc + a
`com.sun.net.httpserver.HttpServer` stub for the Supabase admin call; React 19 + Mantine v9.

**PROGRESS:** Task 2/7 done

## Global constraints

- Free limit: **20** messages per rolling 7 days, property `fpl.quota.free-messages-per-week`,
  env `QUOTA_FREE_MESSAGES_PER_WEEK`. Renamed from `fpl.quota.messages-per-week` (default 50);
  `QUOTA_MESSAGES_PER_WEEK` is not set as a Fly secret, so nothing needs reconciling.
- Account cap: `fpl.invite.max-accounts`, env `INVITE_MAX_ACCOUNTS`, **default 30**.
- Invite code: `fpl.invite.code`, env `INVITE_CODE`, **no value in the repo** — an unset code
  refuses every sign-up.
- New table `fpl_invite_redemption` — `fpl_`-prefixed, additive, created in `UserSchema`, RLS
  enabled with no policies like its four siblings. Test profile pins it to
  `fpl_invite_redemption_test`.
- The plan is **derived, never stored**. No `plan` column, no `fpl_user_subscription`.
- `/api/auth/signup` is the only `permitAll` route under `/api/**`; everything else stays
  `authenticated`, and `anyRequest()` stays `denyAll`.
- Free tells the user its limit; paid (5b) does not. Issue #11's "share, never a count" rule now
  holds for paid only.
- `SUPABASE_SERVICE_ROLE_KEY` is backend-only, never logged, never in the frontend build.
- Every SQL statement goes through `JdbcTemplate` with bound parameters; table names come from
  properties, never hardcoded.

## Two decisions this plan makes that the spec leaves open

1. **`code_label` holds the first 8 hex characters of the SHA-256 of the code that was
   redeemed**, not the code itself. It is what makes a rotation legible ("these six accounts came
   in on the old code") without storing a secret in a table that is not treated as one.
2. **A Supabase that cannot be reached answers `503`, distinct from the `422` it answers when
   Supabase rejects the address or the password.** The spec names 201/403/409/422; an outbound
   call has a fourth outcome, and `FplEntryLookup` already establishes that "could not ask" and
   "the answer is no" must never collapse into one message. A blank service-role key is the same
   outcome and is checked *before* a slot is reserved, so a misconfigured deploy burns no slots.

```java
@Component
public class SupabaseAdminClient {

    private static final Logger log = LoggerFactory.getLogger(SupabaseAdminClient.class);

    private static final Duration CONNECT_TIMEOUT = Duration.ofSeconds(3);
    private static final Duration READ_TIMEOUT = Duration.ofSeconds(10);

    public sealed interface Result {}
    public record Created(UUID userId) implements Result {}
    public record Rejected(String message) implements Result {}
    public record Unavailable() implements Result {}

    private final RestClient restClient;
    private final String url;
    private final String serviceRoleKey;

    public SupabaseAdminClient(RestClient.Builder builder,
                               @Value("${supabase.url}") String url,
                               @Value("${supabase.service-role-key:}") String serviceRoleKey) {
        HttpClient httpClient = HttpClient.newBuilder().connectTimeout(CONNECT_TIMEOUT).build();
        JdkClientHttpRequestFactory factory = new JdkClientHttpRequestFactory(httpClient);
        factory.setReadTimeout(READ_TIMEOUT);
        this.restClient = builder.requestFactory(factory).build();
        this.url = SecurityConfig.collapseDoubledSlash(url + "/auth/v1/admin/users");
        this.serviceRoleKey = serviceRoleKey;
    }

    /** Whether this deploy can create accounts at all. A blank key closes sign-up. */
    public boolean configured() {
        return !serviceRoleKey.isBlank();
    }

    /**
     * Creates a confirmed account. {@code email_confirm} marks the address confirmed without
     * sending anything, which is defensible only while the invite code and the account cap are
     * the gate — see the spec's Open section.
     */
    public Result createUser(String email, String password) {
        try {
            ResponseEntity<Map> response = restClient.post()
                    .uri(url)
                    .header("apikey", serviceRoleKey)
                    .header("Authorization", "Bearer " + serviceRoleKey)
                    .contentType(MediaType.APPLICATION_JSON)
                    .body(Map.of("email", email, "password", password, "email_confirm", true))
                    .retrieve()
                    .onStatus(status -> status.value() == 422 || status.value() == 400,
                            (request, res) -> { })
                    .toEntity(Map.class);
            ...
        } catch (RestClientException e) {
            // Only the failure type: the request body carries a password and the URI carries
            // the project.
            log.warn("Could not reach Supabase to create an account ({})",
                    e.getClass().getSimpleName());
            return new Unavailable();
        }
    }
}
```

   The elided body: a 2xx with an `id` that parses as a UUID is `Created`; a 400/422 is
   `Rejected` with the `msg`/`error_description` field if present and a generic sentence
   otherwise; anything else — including a 2xx whose body has no usable id — is `Unavailable`
   with a WARN naming the status and nothing else. Reject a blank `serviceRoleKey` before the
   call with `Unavailable`, so a misconfigured deploy never sends an unauthenticated request.

   `application.yml` under `supabase`:

```yaml
  # Bypasses row-level security entirely: the same handling class as the database password.
  # Backend only, never logged, never in anything the frontend build can reach. Empty by

  # "unset" that that one did not.
  service-role-key: ${SUPABASE_SERVICE_ROLE_KEY:}
```

3. Implement. `InviteLedger`:

```java
/**
 * The account cap, and the record of who came in on which code.
 *
 * <p>Reserving is a transaction of its own and commits before Supabase is called, which is the
 * whole point: one transaction cannot span Postgres and Supabase, so the only real choice is
 * which way the pair fails when it comes apart. Counting after the account exists fails toward
 * undercounting — an account nobody counted, and a cap that drifts upward silently. Reserving
 * first fails toward overcounting: a burnt row with a null user_id, visible and releasable by
 * hand.
 *
 * <p>The advisory key is constant rather than per user, so every sign-up serialises against
 * every other. That would be wrong for chat; it is right here, because the cap is a global count
 * and the total volume is a few dozen rows for the lifetime of the tier.
 */
@Service
public class InviteLedger {

    private final JdbcTemplate jdbc;
    private final String inviteTable;
    private final int maxAccounts;

    /** Thrown rather than returned: the caller has nothing to do with it but answer 409. */
    public static class CapReachedException extends RuntimeException { }

    @Transactional
    public long reserve(String codeLabel) {
        jdbc.queryForObject("SELECT pg_advisory_xact_lock(hashtext(?))", Object.class, inviteTable);
        Integer taken = jdbc.queryForObject("SELECT count(*) FROM " + inviteTable, Integer.class);
        if (taken >= maxAccounts) {
            throw new CapReachedException();
        }
        return jdbc.queryForObject("INSERT INTO " + inviteTable
                + " (code_label) VALUES (?) RETURNING id", Long.class, codeLabel);
    }

    /** Names the account a reserved slot belongs to, once Supabase has created it. */
    public void assign(long slotId, UUID userId) {
        jdbc.update("UPDATE " + inviteTable + " SET user_id = ? WHERE id = ?", userId, slotId);
    }
}
```

```java
@RestController
@RequestMapping("/api/auth")
public class SignupController {

    public record SignupRequest(String email, String password, String inviteCode) {}
    public record SignupResponse(UUID userId) {}

    @PostMapping("/signup")
    public ResponseEntity<SignupResponse> signUp(@RequestBody SignupRequest request) {
        String email = request == null ? null : request.email();
        String password = request == null ? null : request.password();
        if (email == null || email.isBlank() || password == null || password.isBlank()) {
            throw new ResponseStatusException(HttpStatus.BAD_REQUEST,
                    "An email address and a password are required.");
        }
        // Constant-time, and false for every code while fpl.invite.code is unset: a missing
        // secret closes sign-up rather than opening it.
        if (inviteCode.isBlank() || !MessageDigest.isEqual(
                inviteCode.getBytes(UTF_8),
                (request.inviteCode() == null ? "" : request.inviteCode()).getBytes(UTF_8))) {
            throw new ResponseStatusException(HttpStatus.FORBIDDEN,
                    "That invite code is not valid.");
        }
        // Checked before a slot is reserved: a deploy with no service-role key must not burn
        // one on a call it cannot make.
        if (!admin.configured()) {
            throw new ResponseStatusException(HttpStatus.SERVICE_UNAVAILABLE,
                    "Sign-up is not available right now.");
        }

        long slot;
        try {
            slot = ledger.reserve(codeLabel());
        } catch (InviteLedger.CapReachedException e) {
            throw new ResponseStatusException(HttpStatus.CONFLICT,
                    "Sign-up is full for now. Ask for a place and we will let you know.");
        }

        return switch (admin.createUser(email.trim(), password)) {
            case SupabaseAdminClient.Created(UUID userId) -> {
                ledger.assign(slot, userId);
                yield ResponseEntity.status(HttpStatus.CREATED).body(new SignupResponse(userId));
            }
            // The slot stays burnt. See InviteLedger's javadoc for why that direction is chosen.
            case SupabaseAdminClient.Rejected(String message) ->
                    throw new ResponseStatusException(HttpStatus.UNPROCESSABLE_ENTITY, message);
            case SupabaseAdminClient.Unavailable ignored ->
                    throw new ResponseStatusException(HttpStatus.SERVICE_UNAVAILABLE,
                            "Sign-up could not complete. Please try again shortly.");
        };
    }

    /**
     * The first eight hex characters of the code's SHA-256 — enough to tell one code from
     * another after a rotation, and not the code itself. A ledger row is not a secret store.
     */
    private String codeLabel() { ... }
}
```
